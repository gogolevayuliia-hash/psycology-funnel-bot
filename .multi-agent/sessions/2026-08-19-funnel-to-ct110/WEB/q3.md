# WEB: Настройка пути и secret token Telegram-вебхука в Python-фреймворках

## Ответ
Telegram лишь добавляет настроенный `secret_token` в заголовок каждого webhook-запроса — сам заголовок не заставляет приложение проверять его. Если приложение игнорирует заголовок, запрос будет обработан как обычный и обычно получит штатный `2xx`; поддельные запросы тоже смогут пройти. Если приложение ожидает секрет, а Telegram его не отправляет, aiogram 3 отвечает `401`, встроенный webhook-сервер python-telegram-bot — `403`, а в FastAPI результат определяется вашей реализацией проверки. Любой ответ не из диапазона `2xx` Telegram считает неуспешной доставкой и повторяет запрос.

## Факты и источники
- На стороне Telegram путь задаётся полным HTTPS URL в `setWebhook(url=...)`; `secret_token` должен содержать 1–256 разрешённых символов и при наличии отправляется как `X-Telegram-Bot-Api-Secret-Token`. — https://core.telegram.org/bots/api#setwebhook (Bot API 10.2, 2026)

- В aiogram 3 путь регистрируется отдельно от публичного URL:
  ```python
  WEBHOOK_PATH = "/telegram/webhook"

  SimpleRequestHandler(
      dispatcher=dp,
      bot=bot,
      secret_token=SECRET,
  ).register(app, path=WEBHOOK_PATH)

  await bot.set_webhook(
      f"https://example.com{WEBHOOK_PATH}",
      secret_token=SECRET,
  )
  ```
  `register()` создаёт POST-маршрут; `SimpleRequestHandler` сравнивает заголовок с локальным секретом. — https://docs.aiogram.dev/en/dev-3.x/dispatcher/webhook.html (aiogram 3.30.0)

- В aiogram 3.30.0 при отсутствующем или неверном заголовке возвращаются `401 Unauthorized` и тело `Unauthorized`. Если локальный `secret_token=None`, `verify_secret()` всегда возвращает `True`, даже когда Telegram прислал заголовок. — https://docs.aiogram.dev/en/dev-3.x/_modules/aiogram/webhook/aiohttp_server.html (строки реализации `handle`/`verify_secret`, aiogram 3.30.0)

- В python-telegram-bot путь, публичный URL и секрет обычно задаются одним вызовом:
  ```python
  application.run_webhook(
      listen="127.0.0.1",
      port=8080,
      url_path="telegram/webhook",
      webhook_url="https://example.com/telegram/webhook",
      secret_token=SECRET,
  )
  ```
  `run_webhook()` запускает сервер и сам вызывает `Bot.set_webhook()`; при неверном или отсутствующем заголовке встроенный сервер возвращает `403 Forbidden`. — https://docs.python-telegram-bot.org/en/latest/telegram.ext.application.html#telegram.ext.Application.run_webhook (python-telegram-bot 22.8)

- В FastAPI интеграции Telegram нет: маршрут и проверку задаёт разработчик:
  ```python
  from typing import Annotated
  from fastapi import FastAPI, Header, HTTPException, Response

  app = FastAPI()

  @app.post("/telegram/webhook")
  async def webhook(
      secret: Annotated[
          str | None,
          Header(alias="X-Telegram-Bot-Api-Secret-Token"),
      ] = None,
  ):
      if secret != EXPECTED_SECRET:
          raise HTTPException(status_code=403, detail="Forbidden")

      # разобрать Update и передать диспетчеру
      return Response(status_code=200)
  ```
  FastAPI получает заголовки через `Header`, а код отказа задаётся через `HTTPException(status_code=...)`. — https://fastapi.tiangolo.com/tutorial/header-params/ и https://fastapi.tiangolo.com/reference/exceptions/

- Если в FastAPI объявить заголовок обязательным (`Header()` без `None` и без значения по умолчанию), его отсутствие будет ошибкой валидации запроса, то есть стандартным `422`, ещё до ручного сравнения. Для контролируемого `401/403` его следует принять как необязательный и проверить самостоятельно. — https://fastapi.tiangolo.com/tutorial/header-params/

- При конфигурации «Telegram отправляет секрет, приложение не проверяет» наличие заголовка не изменяет HTTP-ответ: приложение вернёт свой обычный успешный ответ, если обработка Update завершилась успешно. Это не аутентификация, поскольку клиент может обратиться к endpoint без секрета. — https://core.telegram.org/bots/api#setwebhook и https://docs.aiogram.dev/en/dev-3.x/_modules/aiogram/webhook/aiohttp_server.html

- При обратной конфигурации Telegram отправит запрос без заголовка; aiogram вернёт `401`, python-telegram-bot — `403`, FastAPI — заданный разработчиком код либо `422` при обязательном `Header`. Telegram повторяет любой webhook-запрос, получивший не-`2xx`. — https://core.telegram.org/bots/api#setwebhook

## Осторожно
- У python-telegram-bot параметр `secret_token` в `run_webhook()` одновременно передаётся Telegram и включает локальную проверку. Несовпадение сторон обычно возникает только при отдельном ручном вызове `setWebhook`, внешнем provisioning или последующем изменении webhook.
- У aiogram `TokenBasedRequestHandler` не проверяет secret header; документация также не рекомендует его, поскольку bot token находится в URL. Для одного бота следует использовать `SimpleRequestHandler(secret_token=...)`. — https://docs.aiogram.dev/en/dev-3.x/_modules/aiogram/webhook/aiohttp_server.html

## Не нашёл
- Telegram не специфицирует точный график и число повторных доставок: документация говорит только о повторении в течение «разумного количества попыток».
