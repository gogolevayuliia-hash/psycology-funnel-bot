# WEB: Требования Telegram Bot API к webhook-эндпоинту и диагностика ошибок в 2026 году

## Ответ

Telegram принимает webhook только по HTTPS на публичных портах `443`, `80`, `88` или `8443`; TLS требуется даже на порту 80. Сертификат должен соответствовать hostname по CN/SAN, поддерживать TLS 1.2+, а сервер — отдавать полную цепочку промежуточных сертификатов; self-signed допустим, если публичный сертификат передан в `setWebhook`.

Cloudflare Tunnel подходит: Telegram подключается к публичному Cloudflare Edge по `443` с доверенным сертификатом, а внутренний порт приложения может быть любым. Важно не закрывать webhook через Cloudflare Access, интерактивную авторизацию или bot challenge и обеспечить быстрый ответ `2xx`.

`Wrong response from the webhook` означает полученный Telegram HTTP-ответ не из диапазона `2xx`; `read timeout` — ответ вовремя не получен; `502 Bad Gateway` — частный случай неуспешного HTTP-ответа, обычно от прокси или upstream.

## Факты и источники

- Допустимые внешние порты: `443`, `80`, `88`, `8443`. Telegram отправляет HTTPS POST и повторяет доставку, если статус ответа отличается от `2xx`. — https://core.telegram.org/bots/api#setwebhook (актуально на 19.08.2026)
- HTTPS обязателен на любом из поддерживаемых портов; поддерживается TLS 1.2 и выше. — https://core.telegram.org/bots/webhooks
- CN или SAN сертификата должен соответствовать webhook-hostname; необходимо передавать полную цепочку промежуточных сертификатов. SNI поддерживается. — https://core.telegram.org/bots/webhooks
- Self-signed сертификат разрешён, но его публичную PEM-часть нужно загрузить параметром `certificate` как `InputFile`. Redirect при доставке webhook Telegram не поддерживает. — https://core.telegram.org/bots/faq
- Cloudflare Tunnel публикует HTTP-приложения без публичного IP и открытых входящих портов: `cloudflared` устанавливает исходящие соединения с Cloudflare по TCP/UDP `7844`, используя HTTP/2 или QUIC. — https://developers.cloudflare.com/cloudflare-one/networks/connectivity-options/#cloudflare-tunnel (2026)
- Следовательно, ограничение Telegram по портам относится к публичному URL Cloudflare, а не к локальному адресу вида `http://localhost:8080`: TLS завершается на Cloudflare Edge, затем запрос передаётся приложению через Tunnel. Это вывод из архитектуры обоих сервисов. — https://core.telegram.org/bots/webhooks и https://developers.cloudflare.com/cloudflare-one/networks/connectivity-options/#cloudflare-tunnel
- При использовании многоуровневого поддомена стандартный Universal SSL Cloudflare может его не покрыть; может потребоваться Advanced Certificate. — https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/ (23.06.2026)
- `getWebhookInfo.last_error_message` официально определено как человекочитаемое сообщение о последней ошибке доставки; точной классификации строк Telegram не публикует. — https://core.telegram.org/bots/api#webhookinfo
- `Wrong response from the webhook: <status>` означает, что HTTP-ответ получен, но он не `2xx`. По коду обычно различают: `404` — неверный route/path; `401/403` — Access, WAF либо авторизация приложения; `405` — POST не разрешён; `500` — ошибка приложения; `502` — gateway/upstream. Основание — требование Telegram принимать только `2xx`. — https://core.telegram.org/bots/api#setwebhook
- `read timeout` диагностически отличается тем, что Telegram не получил завершённый HTTP-ответ вовремя. Если запрос появился в журнале приложения, но ответ поздний — завис или долго работает handler; если есть только Cloudflare Edge/Tunnel-запись — искать задержку между Tunnel и origin; если нет даже Edge-записи — проверять DNS, TLS и доступность публичного hostname. Точное значение тайм-аута Telegram официально не документировано. — https://core.telegram.org/bots/api#webhookinfo
- Для Cloudflare Tunnel сообщение `502` с текстом `Unable to reach the origin service` означает: Tunnel подключён к Cloudflare, но `cloudflared` не может обратиться к локальному сервису. Типовые причины — приложение не запущено, неверный порт, перепутаны HTTP/HTTPS или не доверен origin-сертификат. — https://developers.cloudflare.com/tunnel/troubleshooting/#i-see-a-502-bad-gateway-error-when-connecting-to-an-http-or-https-application-through-tunnel (29.07.2026)
- Отличать разновидности `502` следует по `cloudflared`-логам и логам приложения: `connection refused` указывает на процесс/порт; malformed HTTP response — на перепутанный протокол; `x509` — на проверку origin-сертификата. Если приложение само зарегистрировало запрос и вернуло `502`, ошибка находится уже в его upstream-цепочке. — https://developers.cloudflare.com/tunnel/troubleshooting/#i-see-a-502-bad-gateway-error-when-connecting-to-an-http-or-https-application-through-tunnel
- Для аутентификации webhook лучше использовать `secret_token`: Telegram передаёт его в `X-Telegram-Bot-Api-Secret-Token`. — https://core.telegram.org/bots/api#setwebhook

## Осторожно

- Telegram не публикует точный порог `read timeout`, поэтому нельзя надёжно отличить медленный handler от сетевой задержки только по `last_error_message`.
- Cloudflare Tunnel скрывает исходный IP от приложения: origin видит адрес `cloudflared`, а исходный HTTP IP передаётся через `CF-Connecting-IP`. Поэтому IP allowlist Telegram непосредственно в приложении требует доверять этому заголовку только после Cloudflare. — https://developers.cloudflare.com/cloudflare-one/networks/connectivity-options/#cloudflare-tunnel
- `last_error_message` хранит только последнюю ошибку; для устойчивой диагностики нужны совпадающие timestamp, Cloudflare Ray ID, Tunnel-логи и журнал webhook-handler.

## Не нашёл

- Официально зафиксированное значение тайм-аута ожидания ответа Telegram webhook.
- Официальный исчерпывающий справочник Telegram по всем возможным строкам `last_error_message`.
