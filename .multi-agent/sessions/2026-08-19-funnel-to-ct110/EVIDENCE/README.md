# EVIDENCE — funnel-to-ct110

## Почему часть проверок идёт ПОСЛЕ merge

Выкат на CT 110 (`deploy.sh`) делает `git -C repo pull --ff-only` из `origin/main` —
другого способа доставить код на контейнер нет. Поэтому живые проверки переключения
физически возможны только после сведения ветки. До merge собрано всё, что можно собрать
без выката, включая проверку секрета на настоящем HTTP-сервере.

| Проверка | Когда | Чем | Вердикт |
|---|---|---|---|
| Тесты через ASGI-стек (К2, К3) | до merge | `pytest` в venv 3.12 | ✅ 16 зелёных |
| Тесты кусаются (мутации) | до merge | ручная порча кода | ✅ обе мутации пойманы |
| Секрет на живом HTTP (К6) | до merge | uvicorn на 127.0.0.1:8757 + curl | ✅ 403 / 403 / 200 |
| Разоружение без `PUBLIC_URL` (К9, предпосылка) | до merge | лог uvicorn | ✅ `PUBLIC_URL not set — webhook not configured` |
| Б1, Б2, К5 «до» | до merge | curl + getWebhookInfo | ✅ `preflight.md` |
| К12 инвентаризация адресов | до merge | grep по Desktop/claude | ✅ найдены `/track` в сайте и Tribute |
| Б7 smoke бота, Б10 рестарт, К5 «после», К7 | **после выката** | bot-test + ssh | ⏳ |
| `/track` со страницы сайта | **после выката** | правка репозитория `site` | ⏳ |

| Мутация | Что сломали | Результат |

| контроль | код восстановлен | ✅ 16 passed |
